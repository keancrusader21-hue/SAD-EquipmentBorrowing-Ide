# Online Equipment Borrowing and Return Monitoring System

BSIT Section B — Systems Analysis and Design — Laboratory Exercise 3

## Stack
- Front End: HTML, CSS, JavaScript (vanilla, no framework)
- Hosting: GitHub Pages
- Backend: Supabase (PostgreSQL + Auth)

## Setup Instructions

### 1. Create a Supabase project
Go to https://supabase.com → New Project.

### 2. Run this SQL in the Supabase SQL Editor

```sql
CREATE TABLE equipment (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    equipment_name TEXT NOT NULL,
    category TEXT NOT NULL,
    asset_code TEXT UNIQUE NOT NULL,
    condition TEXT DEFAULT 'Good',
    availability TEXT DEFAULT 'Available',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE borrow_transactions (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    equipment_id BIGINT REFERENCES equipment(id),
    borrower_name TEXT NOT NULL,
    borrower_type TEXT NOT NULL,
    department TEXT NOT NULL,
    date_borrowed DATE DEFAULT CURRENT_DATE,
    due_date DATE NOT NULL,
    date_returned DATE,
    status TEXT DEFAULT 'Borrowed',
    user_id UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Enable Row Level Security
ALTER TABLE equipment ENABLE ROW LEVEL SECURITY;
ALTER TABLE borrow_transactions ENABLE ROW LEVEL SECURITY;

-- Allow authenticated users to read/write (adjust as needed)
CREATE POLICY "Allow authenticated read equipment" ON equipment
  FOR SELECT USING (auth.role() = 'authenticated');
CREATE POLICY "Allow authenticated write equipment" ON equipment
  FOR ALL USING (auth.role() = 'authenticated');

CREATE POLICY "Allow authenticated read transactions" ON borrow_transactions
  FOR SELECT USING (auth.role() = 'authenticated');
CREATE POLICY "Allow authenticated write transactions" ON borrow_transactions
  FOR ALL USING (auth.role() = 'authenticated');
```

### 3. Create a test user
Supabase Dashboard → Authentication → Users → Add User (email + password).

### 4. Connect the app to Supabase
Open `js/supabase.js` and replace:
```js
const SUPABASE_URL = "YOUR_SUPABASE_PROJECT_URL";
const SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
```
with your values from Project Settings → API.

### 5. Test locally
Open `login.html` in a browser (or use a local server / VS Code Live Server).

### 6. Deploy to GitHub Pages
```bash
git init
git add .
git commit -m "Initial equipment borrowing system structure"
git branch -M main
git remote add origin https://github.com/<username>/SAD-EquipmentBorrowing-<Lastname>.git
git push -u origin main
```
Then enable GitHub Pages: Repo Settings → Pages → Branch: main → / (root).

Live URL will be:
```
https://<username>.github.io/SAD-EquipmentBorrowing-<Lastname>/
```

## Business Rules Implemented
| ID | Rule | Where |
|----|------|-------|
| BR-01 | Equipment name cannot be empty | equipment.js |
| BR-02 | Asset code must be unique | equipment.js + DB UNIQUE constraint |
| BR-03 | Only available equipment may be borrowed | equipment.js (dropdown filter) |
| BR-04 | Borrower name must be provided | transactions.js |
| BR-05 | Due date cannot be earlier than borrowing date | transactions.js |
| BR-06 | Newly borrowed equipment receives Borrowed status | transactions.js |
| BR-07 | Borrowed equipment becomes unavailable | transactions.js |
| BR-08 | Returned equipment becomes available again | transactions.js |
| BR-09 | Equipment past due date identified as Overdue | transactions.js (applyOverdueLogic) |
| BR-10 | Deletion requires confirmation | equipment.js |
| BR-11 | Only authenticated users may manage records | auth.js (requireAuth) |
| BR-12 | A returned transaction cannot be returned twice | transactions.js |
